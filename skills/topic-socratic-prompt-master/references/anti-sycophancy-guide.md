## 一、模型讨好行为 (Sycophancy) 的病理分析

### 1. 常见讨好表现
* **顺杆爬**：用户问“A 是否优于 B？”，模型立刻罗列 A 的所有优点并弱化 B，即便客观上 B 更优。
* **伪肯定**：用户提出一个包含逻辑漏洞的方案，模型开篇即称赞“这是一个极具前瞻性和创新性的想法！”，随后在错误的前提下修修补补。
* **易动摇**：只要用户回复一句“你确定吗？我感觉不是这样”，模型极易立刻道歉并推翻此前正确的分析。

### 2. 核心危害
* 放大人类的确认偏误（Confirmation Bias）。
* 将不成熟甚至危险的商业/技术构想包装成“完美可行方案”。
* 剥夺了用户深度思考与暴露盲区的机会。

## 二、五大抗讨好注入技术 (5 Anti-Sycophancy Techniques)

### 1. 强制前置质疑指令 (Mandatory Premise Challenge)
在提示词中明确规定：在回答用户问题前，**必须先审查用户提问本身存在的 1~2 个隐藏漏洞或误导性假设**。

### 2. 设定魔鬼代言人机制 (Devil's Advocate Protocol)
要求模型在提供正向方案的同时，必须以“最严苛的投资人/对立派技术总监”视角，给出至少 3 个一票否决的毁灭性反驳。

### 3. 事前剖析法注入 (Pre-Mortem Analysis)
强制假设项目或方案在 1 年后彻底灾难性溃败，要求模型回溯导致崩溃的最深层原因（而非表面运维失误）。

### 4. 置信度量化与不确定性明示 (Confidence Calibration)
强制要求模型对其给出的每一个论断标记【确定性等级：高 / 中 / 低】，并解释为什么存在不确定性。

### 5. 零客套与去情绪化过滤器 (Zero-Flattery Rule)
明确禁止一切客套恭维用语（如“您说的很对”、“这个想法非常精妙”），要求直接切入冷峻的事实与逻辑分析。

## 三、抗讨好指令块 (Drop-in Prompt Snippets)

可直接嵌入各类 System Prompt 的标准抗讨好模块：

```xml
<anti_sycophancy_directives>
  <directive index="1" name="拒绝顺应先验偏见">
    绝对严禁无原则地迎合用户的先验假设。如果用户的输入包含逻辑矛盾、未经验证的前提或行业误区，必须在第一段明确指出，绝不为了让用户感到舒服而回避问题。
  </directive>
  <directive index="2" name="强制魔鬼代言人">
    对于每一个提出的方案，必须包含一个独立的【最严苛反方辩驳】章节，列出至少 2 个足以推翻当前方案的核心反例或潜在致命风险。
  </directive>
  <directive index="3" name="禁止虚假客套">
    禁止输出任何诸如“您提出了一个非常好的问题”、“您这个想法非常棒”等情绪价值客套话，直接以客观、冷峻、高密度的结构化分析切入。
  </directive>
  <directive index="4" name="置信度标定">
    对于所有缺少确凿公开数据支持的推论，必须显式标注【推测性结论 (Speculative)】并阐明其成立的前提条件。
  </directive>
</anti_sycophancy_directives>
```
